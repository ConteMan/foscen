# ADR-0004：按需控制面拆成轻量地址条、命令面板与工作面

- 状态：提议（推荐方向 A，待用户审阅）
- 日期：2026-08-22
- 关联：[ADR-0001](0001-electron-view-boundaries.md)、[ADR-0002](0002-trusted-capabilities.md)、[ADR-0003](0003-trusted-window-shell-and-settings.md)
- 三方向：[directions.md](../design/directions.md)
- 推荐规范：[spec.md](../design/spec.md)
- 原型：[prototypes/](../design/prototypes/)

## 背景

当前所有键盘入口（`⌘ L`、`⌘ ⇧ P`、`⌘ S`、`⌘ ,`、`⌘ J`、`⌘ U`）都调用同一个 `showChrome(focusMode)`，控制 View 固定 `530×(窗口宽 − 两侧最多 52px)`。在 1280×800 窗口里这是 `1176×530`；实地在更大窗口中面板几乎横向铺满，命令按钮被拉成超宽条，网页只从底部露出一条。

`⌘ L` 的任务是「打开某个 HTTPS 场景」。它现在做的是「打开整个应用控制台，并把光标放进地址框」。地址框没有建议列表；非法输入（如 `http://`）只把右上角状态改成珊瑚色「仅支持 HTTPS 网页地址」，输入框本身无错误样式。品牌仍用文字 `F`，与 ADR-0003 的随包 SVG 合同不符。

ADR-0003 已经决定：不覆盖 scene 的常驻透明命中区、控制面按需显示、设置留在同一可信控制面。它把控制面一级分类写成「命令、场景、下载、设置」，但没有规定 `⌘ L` 必须复用那块重型面板。

## 决策

### 两层覆盖，同一个 control View

不新增第四个 `WebContentsView`，也不把 control 做成全窗透明层。继续使用现有 control View，按模式计算**紧贴不透明面板**的 bounds：

| 层     | 模式      | 入口                          | 形态                         |
| ------ | --------- | ----------------------------- | ---------------------------- |
| 瞬时层 | `omnibar` | `⌘ L`                         | 地址输入 + 建议列表          |
| 瞬时层 | `palette` | `⌘ ⇧ P`                       | 命令输入 + 动作列表          |
| 工作面 | `surface` | `⌘ S` / `⌘ J` / `⌘ ,` / `⌘ U` | 中等面板，承载表单与审批列表 |

`⌘ L` 的产品定位：**打开或切换到一个 HTTPS 场景**。不是命令中心，不是设置，不是浏览器全能栏。

`⌘ ⇧ P` 的产品定位：**执行桌面动作**（截图、保存场景、打开工作面分区）。与地址条共用视觉语言（输入 + 列表），查询域不同。

工作面一级分类收敛为 **场景、下载、设置**。这细化 ADR-0003：`命令` 不再作为工作面 tab；权限与升级仍按 ADR-0003 进入设置，本 ADR 不提前实现设置框架。

### 布局规则

- 地址条 / 命令面板：宽度 `min(640, 窗口宽 − 48)`，水平居中；顶边 `clamp(72, 14% 窗口高, 140)`。
- 工作面：宽度 `min(720, 窗口宽 − 48)`，高度 `min(420, 窗口高 − 顶边 − 16)`。
- **View 的矩形必须等于可视面板**。透明留白会截获网页点击，这是 ADR-0003 已否决的失败模式。建议列表增减时，renderer 经窄 IPC 上报夹紧后的内容高度，主进程重排 bounds。
- 面板顶部细条保留 `app-region: drag`；输入、按钮、列表必须 `no-drag`。边框模式仍靠 window chrome 顶部外框拖动，不覆盖 scene。

### 建议数据

地址条只匹配 **当前 URL** 与 **已保存场景**（名称、主机、路径）。不为无协议输入做搜索引擎查询，不引入浏览历史或书签仓库。无协议主机按既有 `normalizeSceneUrl` 补 `https://` 并作为「前往」项；显式 `http:`、带凭据、非 HTTPS 协议在输入旁显示错误，不提交导航。

### 点击网页即关闭

control View 只覆盖面板本身。主进程在 scene 收到鼠标按下或重新获得焦点且控制面可见时调用既有 `hideChrome()`。禁止用全窗透明遮罩模拟「点空白关闭」。

## 后果

优点：`⌘ L` 与场景网页同时可见；键盘模型与浏览器地址栏 / Spotlight 一致；工作面尺寸从「应用控制台」降到「必要表单」；安全边界、View 数量、HTTPS-only 不变。

代价：control View 高度随内容变化，需要窄 IPC 与布局测试；地址条与命令面板是两个查询域，实现上要避免又合成一块大面板；点击 scene 关闭依赖主进程事件，而不是 CSS。

## 被否决的方案

- **继续让所有入口共用 530px 多 tab 面板**：与低干扰、键盘优先的产品目标相反，实地评估已确认遮挡过重。
- **一个万能 palette 同时搜地址、场景、命令、下载、设置**：下载审批和权限决定需要表单与明确动作，不适合压缩成一行；也会滑向通用启动器。
- **新增第四个 WebContentsView 专放地址条**：增加生命周期、焦点和销毁路径，收益不足。
- **全窗透明 control 层**：ADR-0003 已否决，会变成网页输入死区。
- **补齐浏览历史、书签、搜索引擎、多标签**：README 明确排除，且会把 Foscen 推向通用浏览器。

## 复审条件

若紧贴 bounds 的动态高度在真实窗口缩放、全屏或极小窗口下无法稳定避免透明命中区，应复审高度算法，而不是扩大 View 或覆盖 scene。设置框架按 ADR-0003 独立交付，不阻塞本决策中的地址条。
